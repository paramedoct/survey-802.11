# 데이터 보존 및 관리 설계

이 문서는 현재 구현을 변경하지 않는 후속 구현 명세다. 첫 단계는 단일 데이터베이스 안에서 반복 문자열과 바이트를 공유하는 스키마 버전 3 전환이다. 월별 파일과 무손실 압축은 별도 후속 단계다. 실제 절감률과 실행 비용은 측정 결과로 판단하며, 정규화만으로 쓰기 횟수나 파일 크기가 반드시 감소한다고 가정하지 않는다.

## 1. 고정 정책과 현재 경계

- 수집 주기는 60초이며 저장 최적화를 위해 늘리거나 줄이지 않는다. 현재 설정 검증은 다른 간격도 허용하지만 이번 작업의 운영 전제는 60초다.
- 사용자에게서 명시적인 삭제 요청을 받기 전까지 모든 저장된 회차와 관측을 영구 보존한다. 자동 삭제, 보관 기한, 오래된 자료의 요약 대체, 이전 회차와 동일하다는 이유의 관측 생략은 금지한다.
- 기존 수집기의 지연 시 예정 회차 건너뛰기는 유지한다. 저장 최적화를 이유로 추가로 건너뛰지 않으며 실제 실행되지 않은 회차를 만들어 넣지 않는다.
- 현재 파서는 한 회차 안에서 같은 주소·주파수 조합의 마지막 완전한 항목만 남긴다. 보존 범위는 현재 `Scan` 객체와 버전 2 데이터베이스에 들어온 값이다. 이번 변경으로 파서가 이미 버린 중복 출력이나 무선 원시 패킷까지 복원하지 않는다.
- 실패, 시간 초과, 취소 회차와 관측이 없는 성공 회차도 모두 저장한다. 실패한 회차의 부분 관측을 저장하지 않는 현재 계약을 유지한다.

근거 코드는 [저장](../src/storage.py), [모델](../src/model.py), [수집 실행](../src/runtime.py), [상태 보고](../src/reporting.py), [백업](../src/backup.py), [사용 설명](../README.md)이다. 현재 스키마는 버전 2이며, `scan` 및 `observation` 테이블과 세 개의 조회 인덱스를 사용한다. 영구 저장은 회차 단위 트랜잭션, 외래 키 검사, `WAL`, `synchronous=FULL` 설정으로 보호된다.

## 2. 반드시 보존할 값과 조회 동등성

| 대상 | 보존 필드 | 의미 및 동등성 기준 |
| --- | --- | --- |
| 회차 | `id`, `device`, `started_at`, `finished_at` | 식별자와 문자열을 그대로 보존한다. 시각의 시간대 표기나 정밀도를 다시 직렬화하지 않는다. |
| 회차 시간축 | `started_monotonic_ms`, `finished_monotonic_ms`, `boot_id` | 정수 밀리초와 부팅 식별자를 그대로 보존한다. 벽시계 변경과 재부팅을 구별한다. |
| 회차 결과 | `status`, `error` | 성공·실패·시간 초과·취소와 오류 문자열을 그대로 보존한다. 빈 오류 문자열도 바꾸지 않는다. |
| 관측 키 | `scan_id`, `bssid`, `frequency_mhz` | 기존 복합 키와 중복 거부 의미를 유지한다. 주소는 기존 소문자 문자열을 그대로 보존한다. |
| 이름 | `ssid_bytes`, `ssid_display` | 원본 바이트와 기존 표시 문자열을 각각 보존한다. 표시 문자열을 원본 바이트에서 재생성하지 않는다. |
| 측정 | `signal_dbm`, `channel` | 실수 신호와 정수 채널 또는 미상 값을 회차별로 보존한다. 채널을 주파수에서 다시 계산하지 않는다. |
| 보안 | `security_json` | 기존 문자열 전체를 보존한다. 키 순서, 공백, 배열 순서가 달라도 원문이 다르면 별도 값이다. |

전환 전후의 `scan` 행과 기존 여덟 관측 열은 키별로 동일해야 한다. 행 개수만 같은 것으로는 충분하지 않다. 문자열·바이트의 내용, 저장 자료형, 미상 여부와 모든 숫자를 비교한다. `NULL`, 빈 바이트 `X''`, 빈 문자열 `''`, 보안 문자열 `'null'`, `'{}'`, `'[]'` 등을 합치지 않는다. 유효하지 않은 빈 보안 문자열은 현재 제약과 같이 거부한다.

기존 두 조회 예제, 회차별·주소별 개수, 특정 주파수 이력, 마지막 회차, 오류 이력, 이름·보안 변화 이력이 동일한 결과를 내야 한다. 명시적 정렬이 없는 쿼리의 행 순서는 계약이 아니다. 기존 조회 예제의 같은 회차 안 여러 주파수 순서까지 고정하려면 `ORDER BY s.id, o.frequency_mhz` 조건을 사용한다. 테이블 내부 식별자나 `rowid`, 직접 쓰기, `sqlite_master` 객체 종류의 일치까지 호환을 약속하지 않는다.

## 3. 버전 3 스키마 결정

`scan` 테이블과 기존 두 회차 인덱스는 그대로 둔다. 주소, 이름, 보안, 이름·보안 조합을 불변 사전으로 분리하고 실제 관측은 매번 한 행씩 기록한다. 다음 정의가 신규 테이블과 조회 호환 뷰의 기준이다. 전환 중 기존 `observation` 테이블은 먼저 `observation_v2` 이름으로 바꾼다.

```sql
CREATE TABLE access_point (
    id INTEGER PRIMARY KEY,
    bssid TEXT NOT NULL COLLATE BINARY UNIQUE
        CHECK (length(bssid) = 17 AND bssid = lower(bssid))
);
CREATE TABLE network_name (
    id INTEGER PRIMARY KEY,
    ssid_bytes BLOB,
    ssid_display TEXT
);
CREATE UNIQUE INDEX network_name_value ON network_name (
    (ssid_bytes IS NULL), coalesce(ssid_bytes, X''),
    (ssid_display IS NULL), coalesce(ssid_display, '') COLLATE BINARY
);
CREATE TABLE security_info (
    id INTEGER PRIMARY KEY,
    security_json TEXT COLLATE BINARY
        CHECK (security_json IS NULL OR json_valid(security_json))
);
CREATE UNIQUE INDEX security_info_value ON security_info (
    (security_json IS NULL), coalesce(security_json, '') COLLATE BINARY
);
CREATE TABLE observation_profile (
    id INTEGER PRIMARY KEY,
    name_id INTEGER NOT NULL REFERENCES network_name(id),
    security_id INTEGER NOT NULL REFERENCES security_info(id),
    UNIQUE (name_id, security_id)
);
CREATE TABLE observation_record (
    scan_id INTEGER NOT NULL REFERENCES scan(id),
    ap_id INTEGER NOT NULL REFERENCES access_point(id),
    frequency_mhz INTEGER NOT NULL CHECK (frequency_mhz > 0),
    profile_id INTEGER NOT NULL REFERENCES observation_profile(id),
    signal_dbm REAL,
    channel INTEGER,
    PRIMARY KEY (scan_id, ap_id, frequency_mhz)
);
CREATE INDEX observation_record_address_time
    ON observation_record(ap_id, scan_id);
CREATE VIEW observation AS
SELECT r.scan_id, a.bssid, r.frequency_mhz,
       n.ssid_bytes, n.ssid_display, r.signal_dbm, r.channel,
       q.security_json
FROM observation_record AS r
JOIN access_point AS a ON a.id = r.ap_id
JOIN observation_profile AS p ON p.id = r.profile_id
JOIN network_name AS n ON n.id = p.name_id
JOIN security_info AS q ON q.id = p.security_id;
```

사전 식별자는 데이터베이스 내부의 대체 키다. 실제 하드웨어의 영구 식별자나 시간 순서로 해석하지 않는다. 특히 다음 규칙을 적용한다.

1. 주소가 같으면 같은 `access_point` 행을 참조한다. 주소 재사용이나 위조 여부는 현재 관측만으로 판별하지 않는다. 이름이 같아도 주소가 다르면 다른 접속점이다.
2. 주파수는 접속점의 고정 속성이 아니다. 같은 주소가 한 회차에 여러 주파수로 나타나도 각각 저장한다. 주파수 변경은 새 접속점을 만들지 않는다. 채널도 관측에 남겨 기존 값과 미래 계산 규칙 변경을 분리한다.
3. 이름 사전은 원본 바이트와 표시 문자열의 쌍을 공유한다. 같은 바이트라도 표시 문자열이 다르면 다른 행이다. 바이트가 다르지만 대체 문자로 같은 표시명이 된 경우도 합치지 않는다. 두 열 중 하나만 미상인 조합도 그대로 허용한다.
4. 보안 사전은 정확히 같은 원문 문자열만 공유한다. 의미상 같은 보안 설정이라도 원문이 다르면 다른 행이다. 미상은 하나의 사전 행에 실제 `NULL` 값으로 저장한다.
5. 이름·보안 조합이 바뀌면 다른 `profile_id` 값을 참조한다. 과거에 사용한 조합으로 돌아오면 기존 행을 다시 참조해도 된다. 버전은 연속 증가 번호나 유효 기간이 아니라 불변 내용의 식별자다. 변화 시점은 관측의 회차로 복원한다.
6. 조합 사전은 주소나 주파수에 종속되지 않는다. 여러 접속점이 같은 이름·보안을 공유할 수 있다. 접속점의 현재 조합을 과거 조회에 덮어씌우는 구조나 시작·종료 구간으로 관측 행을 대체하는 구조는 사용하지 않는다.

주소 사전과 이름·보안을 한 행에 담은 속성 사전 두 개만 두는 대안은 조인과 인덱스 수가 적다. 다만 이름만 바뀌어도 긴 보안 원문을 반복 저장하고, 보안만 바뀌어도 이름 바이트와 표시명을 반복 저장한다. 이번 설계는 독립적인 변화와 여러 주소 사이의 공유를 위해 사전을 더 분리한다. 그 대가로 추가 정수 참조, 고유 인덱스, 사전 조회와 네 번의 조인이 생긴다. 매우 짧거나 매번 다른 값에서는 용량이 늘 수 있으므로 후속 구현의 수용 측정에서 단순 대안도 비교한다. 분리 설계가 운영 목표를 충족하지 못하면 구현 전에 문서를 수정하고 동일 보존 계약으로 다시 검증한다.

일반적인 `UNIQUE` 제약만으로는 여러 미상 행을 합칠 수 없으므로 위 표현식 인덱스를 사용한다. 미상 표시와 대체 값을 함께 비교하여 미상과 빈 값을 구분한다. 문자열은 이진 비교하며 대소문자 접기, 유니코드 정규화, 해시만의 동등성 판단은 금지한다. 저장 모듈은 기존 모델의 자료형을 유지하고 사전 조회에는 `IS ?` 조건으로 각 원본 열을 비교한다. 식별자를 읽을 때는 같은 트랜잭션에서 삽입 또는 기존 값 조회를 수행한다.

사전 네 테이블에는 `BEFORE UPDATE` 트리거를 각각 두고 `RAISE(ABORT, 'immutable dictionary')` 처리한다. 참조 중인 행의 삭제는 외래 키로 거부하고 연쇄 삭제는 설정하지 않는다. 정상 수집과 유지보수에서는 사전 및 관측을 삭제하지 않는다. 사용자 삭제 기능은 별도 명시적 작업이며, 이번 단계에서는 추가하지 않는다. 사전 캐시를 도입한다면 크기를 제한하고 커밋 후에만 항목을 확정한다. 되돌린 트랜잭션의 식별자를 다음 회차에서 재사용하면 안 된다.

## 4. 회차 저장 절차

한 번의 `Storage.save` 호출은 아래 전부를 하나의 트랜잭션으로 처리한다.

1. 현재와 같이 실패 회차에 관측이 들어 있으면 거부한다. `scan` 행을 삽입하고 기존 의미의 회차 식별자를 얻는다.
2. 각 관측에 대해 주소, 이름 쌍, 보안 원문, 조합의 기존 식별자를 조회하고 없으면 삽입한다. 단일 수집기에서도 쓰기 잠금을 잡은 트랜잭션 안에서 처리한다. 중복 충돌 이외의 무결성 오류를 숨기는 포괄적 무시 처리는 사용하지 않는다.
3. 동일한 값의 이전 관측이 있어도 `observation_record` 행을 삽입한다. 신호와 채널을 포함한 관측 복합 키 제약 위반은 회차 전체 실패다.
4. 커밋 성공 후에만 회차 식별자를 반환하고 런타임의 커밋 시각과 성공·실패 카운터를 갱신한다. 사전 삽입을 포함한 어느 단계라도 실패하면 회차 전체를 되돌린다.

수집 주기, 스캔 명령, 파서, 모델의 공개 필드는 바꾸지 않는다. 디스크 부족 시 영구 자료를 지우거나 관측을 생략하지 않고 현재와 같이 실패를 보고한다. 운영자는 외부 저장소 확장 또는 검증된 보존 매체로 이전할 수 있다.

## 5. 전환 원자성과 실패 복구

이번 버전에서는 기존 파일 안에서 한 번의 트랜잭션으로 전환한다. 별도 파일로 교체하거나 여러 번 나누어 커밋하지 않는다. 운영 절차는 수집기를 중지하고 전환 전 일관된 백업을 확보한 뒤 전환 명령을 실행하는 방식으로 확정한다. 대용량 전환을 수집기 시작 경로에 숨기지 않는다. 버전 3 수집기는 버전 2 파일을 만나면 전환 필요를 알리고 쓰기를 거부한다. 전환 명령과 안내는 버전 3 구현과 함께 제공해야 한다.

1. 데이터베이스 경로와 버전을 확인한다. 미지 버전과 데이터가 있는 무버전 파일은 현재와 같이 거부한다. 이 명세의 무손실 전환 입력은 버전 2다. 버전 1 입력은 거부하고 기존 버전 2 업그레이드 절차를 안내한다. 그 절차의 나노초 절삭은 본 명세의 무손실 보장에 포함하지 않는다.
2. 수집 서비스 중지와 단독 실행을 확인하고 별도 전환 잠금을 획득한다. 읽기 전용 조회도 중지하면 장기 읽기가 전환 로그 정리를 막는 상황을 줄일 수 있다. 같은 데이터베이스의 동시 전환과 신규 수집을 막는 잠금 규약은 전환 명령과 수집기 양쪽에서 사용한다.
3. 온라인 백업 기능으로 전환 전 스냅샷을 만든다. 원본, 백업, 새 테이블, 인덱스, 전환 로그에 필요한 여유 공간을 확인한다. 보편적인 배수 하나로 충분하다고 판단하지 말고 측정한 최고 사용량과 안전 여유를 사용한다. 여유가 부족하면 전환 전에 중단한다. 실행 중 공간 부족도 아래 되돌리기 대상으로 처리한다.
4. 외래 키 검사와 기존 내구성 설정을 활성화한 연결에서 `BEGIN IMMEDIATE` 실행 후 버전을 다시 확인한다. 기존 `observation` 이름을 변경하고 새 테이블·인덱스·뷰·불변 트리거를 만든다. `scan` 행과 식별자는 수정하지 않는다.
5. 기존 관측을 일정 크기의 묶음으로 읽어 사전과 사실 테이블에 넣는다. 묶음 크기는 메모리만 제한하고 중간 커밋은 하지 않는다. 전체 원본을 메모리로 읽지 않는다. 값 비교와 삽입 규칙은 신규 저장과 동일하다.
6. 기존 테이블과 새 조회 뷰를 비교한다. 총 행 수와 회차별 행 수, 복합 키 유일성, 모든 열의 값·자료형·미상 여부를 검사한다. 키 정렬 후 두 커서를 순차 비교하는 방식으로 큰 파일에서도 전체 동등성을 검사한다. 샘플 검사나 해시 하나만으로 원본 삭제를 승인하지 않는다. `scan` 원본도 전환 전 백업과 전체 비교한다.
7. `PRAGMA foreign_key_check` 결과가 비어 있고 `PRAGMA integrity_check` 결과가 `ok` 인지 확인한다. 기존 테이블을 삭제하면 기존 `observation_address_time` 인덱스도 제거된다. `PRAGMA user_version = 3` 변경과 최종 검증 후 같은 트랜잭션을 커밋한다. 이미 시작한 트랜잭션 안에서 암묵적 커밋을 유발하는 `executescript` 호출을 섞지 않는다.
8. 연결을 닫고 새 연결로 버전, 조회 예제, 요약과 무결성을 확인한 다음 수집을 재개한다. 중지 시간은 전환 작업 이력에 기록한다. 미수집 구간에 가상의 성공 회차를 넣지 않는다.

커밋 전 예외나 중단은 전체 되돌리기 대상이다. 프로세스 강제 종료나 전원 차단 후에는 데이터베이스 복구를 먼저 수행하고 버전을 읽는다. 버전 2라면 원래 스키마가 유지된 상태에서 재시도하고, 버전 3이라면 새 스키마를 검증하여 계속한다. 중간 객체만 남은 상태를 정상 완료로 인정하지 않는다. 복구 실패 시 원본 파일과 로그를 보존하고 별도 백업에서 복원한다. 기존 파일에 과거 `WAL` 파일을 섞지 않는다.

전환 직후 파일 크기는 줄지 않을 수 있다. 삭제된 원본 테이블의 페이지는 파일 안의 빈 공간으로 남아 이후 삽입에 재사용된다. 파일 축소가 필요하면 전환 완료·검증·백업 후 별도 유지보수로 공간과 중지 시간을 확보해 `VACUUM` 작업을 수행한다. 이는 전환 커밋과 분리하며 실패하더라도 정상 버전 3 파일과 백업을 유지한다. 자동 실행이나 절감량 과장에 사용하지 않는다. 로그 정리와 파일 축소 전후의 크기를 구별해 측정한다.

## 6. 조회·상태·백업 영향

| 기능 | 버전 3의 계약과 구현 작업 |
| --- | --- |
| 기존 직접 조회 | `observation` 이름과 열 순서를 읽기 전용 뷰로 보존한다. 사용 설명의 두 예제를 그대로 실행할 수 있어야 한다. 직접 삽입·갱신은 저장 모듈로 이전한다. |
| 주소 이력 | 주소의 고유 인덱스와 사실 테이블의 주소·회차 인덱스를 사용한다. 실행 계획과 대표 이력 조회 지연을 측정한다. 추가 조인의 비용을 확인한다. |
| 시간 이력 | `scan_time`, `scan_boot_time` 인덱스를 그대로 보존한다. 주파수는 관측에서 읽는다. |
| 영구 요약 | `read_summary` 함수가 버전 3을 읽도록 버전 허용 목록을 수정한다. 현재 `scan` 기반 집계, 마지막 회차·오류 선정, 반환 필드와 식별자 의미는 유지한다. 전환 전 상태 확인을 위해 버전 2 읽기도 유지한다. |
| 런타임 상태 | 기존 회차별 상태와 프로세스 카운터 의미를 유지한다. 상태 파일이 과거 프로세스를 가리킬 수 있다는 기존 제한도 같다. |
| 저장 공간 표시 | 단일 파일 및 두 보조 파일의 합계를 유지한다. 전환 백업과 임시 파일은 현재 합계에 포함되지 않으므로 전환 명령에서 별도 경로·용량을 보고한다. |
| 백업 | 현재 온라인 백업 방식으로 사전·사실·뷰·인덱스·트리거·버전을 함께 포함한 일관된 스냅샷을 만든다. 원본 파일을 직접 전송하지 않는다. |
| 복원·구버전 프로그램 | 복원한 버전 3 파일은 버전 3 지원 프로그램으로 연다. 기존 프로그램은 버전 거부가 정상이다. 구버전으로 되돌릴 때는 전환 전 백업을 별도 보존하며 이후 수집 자료를 버리는 덮어쓰기를 하지 않는다. 무손실 역전환 도구는 이번 단계 범위 밖이다. |

백업 파일은 전송 성공만으로 검증 완료가 아니다. 복원 사본을 열어 무결성·외래 키·조회 동등성을 확인한다. 관리자가 요청하기 전까지 전환 전 백업을 자동 삭제하지 않는다.

## 7. 월별 독립 파일과 무손실 압축의 후속 조건

월별 분할은 버전 3과 함께 구현하지 않는다. 아래 조건을 모두 만족하는 별도 설계와 측정이 선행되어야 한다.

- 각 월 파일은 해당 회차와 관측뿐 아니라 참조한 사전 행, 스키마, 버전을 자체 포함한다. 공유 전역 사전 파일 없이는 해석할 수 없는 구조를 금지한다. 내부 사전 식별자는 파일마다 달라도 된다.
- 월의 기준은 회차 시작 시각을 협정 세계시로 변환한 연월로 정한다. 원래 시각 문자열은 그대로 보존한다. 월 경계에 걸친 회차는 나누지 않는다. 시계 역행이나 과거 월로 향하는 신규 회차도 유실 없이 저장할 수 있어야 하므로 단순히 지난 달 파일을 영구 봉인하는 구현은 불가하다.
- 기존 단일 파일의 회차 식별자를 보존하고 후속 삽입에도 수집 집합 전체에서 단조 증가하는 식별자를 할당한다. 파일 간 원자성, 중복 할당 방지, 장애 후 재시도와 월별 이동 기록을 보장하는 절차를 별도 확정한다. 파일마다 `id = 1` 시작은 기존 상태·조회 계약과 맞지 않는다.
- 전체 기간 조회는 모든 관련 파일을 합치고 원래 회차 식별자 또는 부팅·단조 시각 기준으로 정렬한다. 전체 요약의 회차 수, 마지막 회차·오류, 복합 키 중복 검사가 단일 파일과 동등해야 한다. 각 파일의 직접 조회와 전체 조회 인터페이스를 함께 제공한다.
- 파일 목록과 버전·크기·검증값을 관리하는 목록 파일의 원자적 갱신, 누락·중복 검출, 목록 자체의 복구를 정의한다. 파일 수가 많아도 한꺼번에 모두 연결하지 않는 조회 방식이 필요하다.
- 백업은 고정된 파일 목록과 각 파일의 일관된 스냅샷을 묶는다. 진행 중 월 전환이나 수정 때문에 같은 회차가 빠지거나 두 번 들어가지 않도록 전체 집합의 경계를 고정해야 한다. 복원은 모든 파일을 검증한 후 집합 단위로 공개한다.
- 공간 상태는 활성·보관·압축 파일, 임시 해제 파일, 로그와 백업 작업의 최고 공간을 구분해 보여준다. 현재 단일 파일 상태 및 백업 함수만으로 월별 구조를 지원한다고 간주하지 않는다.

압축은 닫힌 일관된 데이터베이스 스냅샷에만 적용한다. 활성 파일이나 필요한 로그를 제외한 주 파일만 압축하지 않는다. 최초 후속 구현은 외부 의존성 없는 `gzip` 형식의 독립 파일을 기본 후보로 측정하며, 형식 확정은 실측 후 결정한다. 이는 요약이나 손실 인코딩이 아니다. 해제 후 데이터베이스 파일의 모든 바이트가 같아야 하며, 압축 전 원본과 해제본의 크기·강한 검증값 및 데이터베이스 검사를 확인한다.

압축 파일은 임시 경로에 쓰고 동기화·검증한 뒤 원자적으로 공개한다. 압축 사본을 확인하기 전 원본을 제거하지 않는다. 원본 경로 정리는 보존 대체물이 검증된 이후의 저장 표현 전환이며, 구현 전 사용자 보존 정책과 복구 절차를 명확히 문서화한다. 압축 사본까지 삭제하는 보관 만료 정책은 두지 않는다. 과거 월 수정 시 안전하게 해제·갱신·재압축·교체할 수 있어야 하고, 조회의 임시 해제 공간과 지연도 측정한다. 압축은 백업의 대체물이 아니다.

## 8. 구현 수용 기준과 미해결 사항

버전 3 구현의 필수 검증은 다음과 같다.

- 이름 미상·빈 이름·비정상 문자·내장 영 바이트, 표시명만 같은 서로 다른 바이트, 같은 바이트의 다른 표시명, 보안 미상·원문 순서 변경·설정 복귀를 포함한 전체 동등성 검사.
- 같은 주소의 여러 주파수, 같은 이름의 여러 주소, 매번 같은 값, 매번 바뀌는 값, 신호·채널 미상을 포함해 모든 관측 수가 유지되는지 검사.
- 빈 성공과 세 실패 상태, 회차 식별자·오류 이력·시간대 문자열·단조 시각이 보존되는지 검사.
- 사전 삽입 중 오류, 사실 삽입 중 오류, 전환 중 디스크 부족, 커밋 전후 강제 종료, 재시도, 복원 사본에서 조회와 참조 무결성 검사. 과거 관측이 새 설정에 의해 바뀌지 않는지 검사.
- 기존 조회 예제와 상태 반환값 회귀 검사, 정상 백업·복원 검사, 미지원 버전 거부 검사.
- 대표 규모에서 정규화 전후의 데이터베이스·로그·인덱스 포함 용량, 회차 커밋 지연, 메모리 최고 사용량, 조회·백업·전환 시간과 전환 최고 디스크 사용량 비교. 파일 축소 전후를 구별하고 하드웨어 검증 전에는 실장 장비의 수명·속도 개선을 단정하지 않는다.

다음은 정책이나 데이터 모델 결정을 미루는 항목이 아니라 후속 구현·운영 단계의 인수사항이다.

| 항목 | 결정에 필요한 증거 또는 작업 |
| --- | --- |
| 사전 캐시·읽기 묶음 크기 | 제한된 메모리의 실제 장비에서 최고 메모리와 회차 커밋 지연 측정. 캐시 없이도 의미가 동일해야 한다. |
| 전환 명령 이름·공유 잠금 위치 | 실행·서비스 관리 경로를 포함한 구현 검토. 잠금과 명시적 전환이라는 결정은 고정이다. |
| 전환 여유 공간·중지 창 | 실제 크기의 복제본에서 최고 공간과 소요 시간 측정. 전환 전 운영 안내에 수치 제시. |
| 월별 파일의 다중 파일 원자성 | 회차 할당·이동·복구·전체 백업을 포함한 별도 설계 승인과 장애 주입 검증. |
| 압축 형식·보관 표현 교체 | 실제 압축률·해제 시간·임시 공간 측정 및 원본 대체 절차 검토. 첫 단계에서 자동 적용하지 않음. |

이 문서 자체는 스키마 전환이나 보존 정책 변경을 실행하지 않는다. 첫 구현은 위 버전 3 정규화, 명시적 원자 전환, 조회·상태·백업 호환과 검증까지만 포함한다.
