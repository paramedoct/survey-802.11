# 저장 정규화 결과

버전 3은 주소·이름·보안·속성 조합의 불변 사전을 공유하고 모든 관측을 회차마다 보존한다. 수집 주기는 60초 그대로다. 사용자 요청 없는 삭제, 보관 기한, 관측 생략, 요약 대체는 추가하지 않았다. 월별 파일과 압축은 이 변경의 범위 밖이다.

## 동일 입력 비교

[기준 결과](storage-baseline-results.json)와 [정규화 결과](storage-normalization-results.json)는 같은 합성 생성기, 조건별 1,440회, 같은 저장·조회 경로를 사용했다. 각 조건의 입력 SHA256 일치를 확인했다. 크기는 로그 정리 후 파일 전체로 테이블과 인덱스를 포함한다. 이력은 한 주소의 1,440행 전체를 읽는 기존 쿼리이며 30회 재조회 중앙값이다. 저장 시간은 모든 회차 커밋 누적 시간이다.

| 조건 | 기존 바이트 | 정규화 바이트 | 절감률 | 이력 기존/정규화 ms | 저장 기존/정규화 s |
| --- | ---: | ---: | ---: | ---: | ---: |
| base | 20,094,976 | 4,161,536 | 79.3% | 1.838/1.288 | 0.292/0.603 |
| ap10 | 4,304,896 | 1,134,592 | 73.6% | 1.526/1.263 | 0.077/0.149 |
| ap200 | 79,491,072 | 16,142,336 | 79.7% | 1.962/1.960 | 1.198/2.515 |
| ssid8 | 18,751,488 | 4,161,536 | 77.8% | 1.910/1.254 | 0.304/0.603 |
| ssid32 | 22,704,128 | 4,161,536 | 81.7% | 1.833/1.254 | 0.297/0.618 |
| security64 | 15,167,488 | 4,161,536 | 72.6% | 1.920/1.245 | 0.310/0.602 |
| security512 | 47,546,368 | 4,161,536 | 91.2% | 2.048/1.326 | 0.336/0.597 |
| change60 | 20,094,976 | 4,370,432 | 78.3% | 2.002/1.267 | 0.318/0.620 |
| change1 | 20,094,976 | 13,463,552 | 33.0% | 1.937/2.279 | 0.307/1.011 |

기준 조건에서 파일 크기는 79.3% 감소했고 매회 이름이 바뀌는 조건에서도 33.0% 감소했다. 다만 저장 작업은 대략 두 배 이상 느려졌으며, 매회 변경 조건의 이력 조회도 느려졌다. 추가 사전 조회·조인이 비용을 만든다. 반복 문자열이 긴 조건에서 효과가 크다. 모든 값이 매번 고유한 다른 입력에서는 증가할 수도 있다. 이번 측정으로 분리 사전 구조를 유지했으며 대체 두 사전 구조를 별도 구현해 비교하지는 않았다.

실행 환경과 조회 계획, 객체별 크기, 관측당 증가량, 일/30일 외삽, 로그·공유 메모리 및 파일 합계 최고치는 결과 JSON에 보존했다. 로그 최고치는 회차 커밋 후 표본이므로 순간 최고치가 아니다. 로컬 임시 저장소의 합성 결과이며 실제 장비의 지연·수명·물리 쓰기 절감을 의미하지 않는다. 저장 지연의 백분위와 장기 실장 장비 측정은 수행하지 않았다.

## 기존 파일 전환

[전환 결과](storage-migration-results.json)는 기준 조건의 72,000개 관측을 사용했다. 원본 20,094,976바이트에서 전환 직후 23,896,064바이트로 커졌으며 이 중 19,726,336바이트는 재사용 가능한 빈 페이지다. 별도 파일 축소 후 3,842,048바이트였다. 신규 파일 측정과 페이지 배치가 달라 크기가 같지는 않다.

백업과 전체 값·자료형 검증을 포함한 전환은 1.363초, 전환 중 원본·백업·로그 합계의 표본 최고치는 63,924,920바이트였다. 10ms 간격으로 표본을 읽었고 프로세스 상주 메모리 최고치는 35,586,048바이트였다. 전환 후 백업은 0.010초, 별도 파일 축소는 0.011초였다. 이 결과만으로 대용량 운영 전환 여유 공간을 결정하지 않는다. 원본 복제본으로 재측정하고 중지 창과 여유 공간을 확보한다. 자동 파일 축소나 백업 삭제는 하지 않는다.

```sh
PYTHONPATH=src .venv/bin/python tools/storage_baseline.py --output /tmp/normalized-results.json
PYTHONPATH=src .venv/bin/python tools/storage_migration_benchmark.py --output /tmp/migration-results.json
```

## 검증과 운영 경계

전용 테스트는 모든 관측 필드, 미상·빈 값·내장 영 바이트·잘못된 문자 바이트, 같은 표시명의 다른 바이트, 다른 표시명의 같은 바이트, 보안 원문 차이, 다중 주파수, 속성 변경·복귀, 재시작, 실패 회차와 빈 성공을 비교한다. 사전 갱신 거부, 중복 및 무효 보안값의 회차 전체 되돌리기, 전환 중 오류, 기존 백업 덮어쓰기 거부, 동시 저장 잠금, 커밋 전후 강제 종료 후 복구와 재시도도 검증한다. 정상 저장 경로의 공간 부족 검사는 기존 테스트로 유지한다. 전환 공간 부족은 삽입 중 오류 주입이며 실제 파일시스템 소진이나 전원 차단 시험은 아니다.

버전 2 전환은 명시적 명령이며 원문을 다시 직렬화하지 않는다. 기존 조회는 읽기 전용 호환 뷰를 사용한다. 상태와 온라인 백업의 인터페이스는 유지한다. 외부 직접 쓰기 및 테이블 내부 식별자는 호환 계약이 아니다. 버전 1은 구버전 프로그램의 버전 2 전환을 먼저 요구하며 기존 나노초 절삭은 이번 무손실 보장에 포함하지 않는다. 설치 전에 서비스를 중지하는 순서와 전환·복구 절차는 README에 안내한다.
